# Sign-up, password reset and login links

`modules/signup` is for projects that need self-service accounts. djext is B2B, so it starts off. Three settings turn it on; the first two need `AUTH_PASSWORD`:

- **`AUTH_SIGNUP=True`:** anyone can sign up with email and password at `/signup`. The account stays inactive until they open the link sent by email (`/verify`): that confirms it and takes them to the login. Logging in before that with the right password says the email isn't confirmed and sends a new link, within the limits below (`inactive_login`), so an expired link is no dead end, and it is not counted as a failed login; a wrong password still gets "Invalid email or password". Signing up again before that replaces the password and kills the earlier links. Only accounts created this way get activated by a link (the `Signup` row). A user the team blocked or anonymized stays inactive. A dead link offers to send a new one.
- **`AUTH_PASSWORD_RESET=True`:** "Forgot your password?" on `/login` sends a link to choose a new one (`/reset-password`). Only active users who have a password get one. A new password ends all of that user's sessions (`auth.end_sessions`) and lifts the login lock on their email: `authd` listens for `auth.password_reset`.
- **`AUTH_MAGIC_LINK=True`:** "Email me a login link" on `/login` sends a link that logs in (`/login-link`), with or without a password, also with `AUTH_PASSWORD` off (then the login page asks only for the email). Like the providers, it signs nobody up: only active users get one. Opening the link shows a "Log in" button and the button logs in, so a mail scanner that opens it doesn't use it up. It works once: it is made from the last login, so any login kills it, and so does a new password. It carries the page to go to afterwards (`next`, a path here only). The login is logged with the method `login_link`.

The links use Django's `PasswordResetTokenGenerator`, so no tokens are stored. They expire after `PASSWORD_RESET_TIMEOUT` (1 hour). A reset or login link works once; a verification link opened again (a second device, a mail scanner) says the account is confirmed, and without its token the `uid` tells nothing. They are built from the host the Next proxy sends, so the frontend's host must be in `ALLOWED_HOSTS`, as for `oauth`.

The endpoints that take an email (sign up, resend the verification, forgot the password, ask for a login link) always answer 204, whether the email has an account or not. Only the inbox learns it: signing up with an email that has an account sends `account_exists` (a login link, and the reset if it is on), and "forgot" or a login link for an account still waiting sends its confirmation link. The time they take still differs a little (a new account is written to the database, an existing one is not), so a patient attacker timing many tries may tell them apart; the limits below make that slow. They are limited per address and per IP (`AUTH_MAIL_THROTTLE_EMAIL`, `AUTH_MAIL_THROTTLE_IP`), with the confirmation links, the resets and the login links counted apart; past a limit they answer 429, say how long to wait, and send nothing. Signing up, verifying, asking for a reset or a login link and resetting are logged as `auth.*` actions (`action_performed`), always with the user as the target.

The emails are the `verify_email`, `password_reset`, `account_exists` and `login_link` templates in the admin (Post Office › Email templates). The migrations create them, and an edited one is left as it is. In development the worker prints them, links included (see `mail`).

## Depends on

`mail` (django-post-office) to send the emails. The login page shows the links when `/api/auth/providers` says `signup`, `password_reset` or `magic_link` is on.

## Removing it

Delete `backend/modules/signup/` and these lines: `INSTALLED_APPS` and the `AUTH_SIGNUP` / `AUTH_PASSWORD_RESET` / `AUTH_MAGIC_LINK` / `PASSWORD_RESET_TIMEOUT` / `AUTH_MAIL_THROTTLE_*` block in `config/settings.py`, the import and `add_router` in `config/urls.py`, the `Signup` lines in `User.anonymize()` (`apps/authd/models.py`), and the matching lines in `.env.example`. On the frontend, delete `app/signup/`, `app/verify/`, `app/forgot-password/`, `app/reset-password/`, `app/login-link/`, `components/account-forms.tsx`, `e2e/signup.spec.ts` and `e2e/login-link.spec.ts`, and the `AUTH_SIGNUP` / `AUTH_PASSWORD_RESET` / `AUTH_MAGIC_LINK` env of the backend in `playwright.config.ts`. Then run `make api-types`. The links on `/login`, `getLoginOptions` (`lib/auth.ts`) and the pages in `PUBLIC_PAGES` (`lib/login-guard.ts`) can stay: `/api/auth/providers` says they are off. Its table and email templates stay in the database until you drop them.
